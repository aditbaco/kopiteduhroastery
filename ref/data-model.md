# Data Model

Prisma 7.8 against MySQL/MariaDB (Laragon locally). Prisma 7 changes several things versus
Prisma 5/6 — see [Prisma 7 specifics](#prisma-7-specifics) before touching config.

## Schema — `prisma/schema.prisma`

### Enums

| Enum | Values |
| --- | --- |
| `Species` | `ARABICA`, `ROBUSTA` |
| `Process` | `WASHED`, `NATURAL`, `HONEY`, `WINE`, `WET_HULLED` |
| `RoastLevel` | `LIGHT`, `MEDIUM_LIGHT`, `MEDIUM`, `MEDIUM_DARK`, `DARK` |

Enum values are used directly as dictionary keys (`dict.process.WASHED`), so adding an enum
value means adding it to both `src/dictionaries/id.ts` and `en.ts` or the label lookup
breaks. See [i18n.md](i18n.md).

### Models

**`Product`** — the coffee lot. `slug` is the URL key and is unique.
Origin fields: `origin`, `regency`, `province` (defaults `"Sulawesi Tengah"`),
`altitudeMin` / `altitudeMax` in mdpl. Character: `species`, `process`, `roastLevel`.
Provenance: `producer?`, `partnerSince?`. Display: `heroImage?`, `isActive`, `isFeatured`,
`sortOrder`. Bilingual pairs: `name`/`nameEn?`, `shortDesc`/`shortDescEn?`,
`description`/`descriptionEn?`.
Relations: `varietals`, `tastingNotes`, `variants`, `images`.
Indexes: `[isActive, sortOrder]`, `[species]`.

**`ProductVariant`** — a purchasable SKU: `weightG` (200 / 500 / 1000), `priceIdr`, `sku`
(unique), `isDefault`, `isActive`, `sortOrder`. `@@unique([productId, weightG])`.

**`TastingNote`** — ordered `label` / `labelEn?` per product.

**`ProductImage`** — `url`, `alt` / `altEn?`, `sortOrder`.

**`Varietal`** + **`ProductVarietal`** — many-to-many via an explicit join model with a
composite primary key.

**`GrindOption`** — a standalone global lookup with no product relation: `slug`, `name` /
`nameEn?`, `note` / `noteEn?`, `isDefault`, `isActive`, `sortOrder`. Every product offers
every active grind.

All child FKs are `onDelete: Cascade`.

### Deliberate design decisions

- **Prices are plain integer rupiah** (`Int`), not `Decimal`. IDR has no minor unit in
  practice; formatting is `src/utils/format.ts:formatIdr`.
- **Indonesian is required, English is nullable.** English translations can be filled in
  gradually; the storefront falls back via `pickLocalized`. See [i18n.md](i18n.md).
- **There is no `Order` model, and that is intentional.** Checkout is a WhatsApp handoff and
  the cart lives in browser `localStorage`. See [storefront.md](storefront.md).

## Prisma 7 specifics

Three things differ from older Prisma and will bite if reverted:

1. **Generator is `prisma-client`**, not `prisma-client-js`, and outputs TypeScript to
   `../src/generated/prisma`. Import from `@/generated/prisma/client`, not
   `@prisma/client`. That directory is gitignored and regenerated by `prisma generate`.
2. **The datasource block has no `url`.** The connection string moved to `prisma.config.ts`
   (`datasource: { url: env<Env>('DATABASE_URL') }`), which also declares the schema path,
   migrations path, and the seed command.
3. **A driver adapter is required.** `src/libs/prisma.ts` constructs
   `new PrismaMariaDb(process.env.DATABASE_URL)` from `@prisma/adapter-mariadb` and passes
   it as `new PrismaClient({ adapter })`. The client is cached on `globalThis` outside
   production so dev hot-reload doesn't leak connections.

## Data access — `src/libs/products.ts`

The only place application code queries the database. Marked `import 'server-only'`.

Every query is wrapped in `unstable_cache` and tagged `PRODUCTS_TAG` (`'products'`), so a
future admin write path can `revalidateTag('products')` instead of forcing a rebuild.

A shared `productInclude` pulls active variants, ordered tasting notes, varietals (through
the join), and images — all ordered by `sortOrder`.

| Export | Returns |
| --- | --- |
| `getProducts()` | Active products ordered by `sortOrder` |
| `getFeaturedProducts()` | Same, filtered to `isFeatured` |
| `getProductBySlug(slug)` | One active product, or null |
| `getGrindOptions()` | Active grind options, ordered |
| `PRODUCTS_TAG` | The revalidation tag |
| `ProductWithRelations`, `GrindOptionRecord` | Types inferred from the queries |

There are no API routes. Writes happen only through the admin's Server Actions, which use
separate uncached, unfiltered read layers (`src/libs/admin/products/read.ts`,
`src/libs/admin/varietals/read.ts`) and transactional mutation layers, then invalidate
`PRODUCTS_TAG`. `Product` and its children are edited at `/admin/products`; `Varietal` at
`/admin/settings`. Every other model is still seed-only. See
[admin-dashboard.md](admin-dashboard.md).

> **Deleting a `Varietal` is guarded in code, not by the schema.** `ProductVarietal` has
> `onDelete: Cascade` on both sides, so a raw delete would strip the varietal from every
> product silently. `deleteVarietal()` refuses when the link count is non-zero.

## Migrations and seed

One migration so far: `prisma/migrations/20260719063824_init`. Tables are
`utf8mb4` / `utf8mb4_unicode_ci`.

`prisma/seed.ts` runs under `tsx`, loads its own `dotenv/config` and builds its own client.
It deletes children-first, then inserts 6 varietals, 6 grind options
(biji-utuh, v60, espresso, tubruk, french-press, vietnam-drip) and 5 products:
`arabika-sulawesi-lore`, `lore-wuasa`, `lembah-besoa`, `robusta-sulawesi-lore`,
`robusta-sulawesi-tojo`. SKUs are derived via `skuFor(slug, weightG)` →
`KTR-<abbrev>-<grams>`.

> **The seed contains placeholder data.** Its header flags prices, tasting notes, producer
> names, partnership years, process, roast level, and descriptions as unconfirmed. These
> need client sign-off before launch.

## Database workflow

```bash
pnpm db:generate   # prisma generate — after any schema.prisma edit
pnpm db:migrate    # prisma migrate dev — create + apply a migration
pnpm db:seed       # tsx prisma/seed.ts — wipes catalog tables, reinserts
pnpm db:studio     # prisma studio
```

`pnpm db:reset` maps to `prisma migrate reset`, which **drops and recreates the database**.
Do not run it against anything holding real data.
